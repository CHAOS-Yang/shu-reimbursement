# shu-reimbursement

> 上海大学财务报销 Agent Skill —— 判经费卡类型、匹配适用办法、核对票据、填写报销单与审批单、排版导出 PDF、生成提交包。

**v2.0.0** · MIT · 面向 上大内〔2026〕127 号 / 128 号（2026-07-30 施行）

> **致谢起点**
> 本项目起步于 [**@Prism-Lab-SHU**](https://github.com/Prism-Lab-SHU) 的
> [**SHU-reimbursement**](https://github.com/Prism-Lab-SHU/SHU-reimbursement)（MIT）。
> 上游把「票据扔进去 → 自动分类 → 发票配对 → 填表 → 缺件检查」这条链路搭通了，
> 本仓库是在它之上继续走了两年真实报销之后的版本：
> 规则更新到 2026 年新办法、坐标精确到单元格、排版与导出做成可核验的工具链。
> 哪些是承袭的、哪些是改进的，见 [**相对上游的改进**](#相对上游的改进)。

## 这是什么

一个给 AI Agent 用的**技能包**（skill），不是文档站，也不是报销系统。

它把「高校财务报销」这件高度依赖经验的事，拆成了 Agent 能执行的东西：

- **规则**：哪张卡适用哪个办法、限额多少、什么情况不能报
- **坐标**：表格里第几行第几列该填什么（含 2026 版相对 2019 版挪动的格）
- **工具**：把 xlsx 按真实几何渲染成 PDF、逐格像素核验、zip 级 XML 补丁
- **坑**：一份清单，每条对应一次真实返工

## 为什么值得单独做一个 skill

通用模型能背出差旅标准，但下面这些它不会知道：

| 问题 | 通用模型 | 本技能 |
|------|----------|--------|
| 这张 `D.xx` 卡走哪个办法？ | 不知道要判卡 | 首字母 `D V L` → 128 号，限额更高、无 3 天限制 |
| 出差审批单经费账号填哪格？ | 编一个 | 2026 版 `A19` 标签 / `C19` 值（2019 版是 A17/C17） |
| 导出 PDF 后 `1029.87` 变成「1029 87」？ | 猜是字体问题 | 先 `pdffonts` 找无 ToUnicode 的 ASCII 子集，再决定是改列宽还是换渲染 |
| 2 人合住的住宿费能整笔报吗？ | 能 | **不能**，限额是元/人·天，必须分摊并附说明 |
| 学会会费放差旅单「其他费用」？ | 合理 | **超范围列支**，会被退 |

这些结论来自**真实的退单、被清空的表格、打不出来的 PDF**。

## 快速开始

> 装一次，之后每次报销都是三步：**扔票据 → 说一句话 → 验收提交包**。

### 一、安装（一次性，约 2 分钟）

**方式 A · 装进 Agent（推荐）**

```bash
git clone https://github.com/CHAOS-Yang/shu-reimbursement.git \
  ~/.workbuddy/skills/shu-reimbursement

# Claude Code 用户改路径即可：
# git clone https://github.com/CHAOS-Yang/shu-reimbursement.git \
#   ~/.claude/skills/shu-reimbursement
```

**装完验证**：新开一个对话，问它一句

> 上海的差旅报销，2026 年 7 月 30 日之后的出差按哪个办法？

能答出「127 号（非科研）/ 128 号（科研），`D V L` 卡走 128 号」就算加载成功。
答不出来通常是目录名不对——必须是 `shu-reimbursement`，且该目录下**直接**有 `SKILL.md`。

**方式 B · 只用命令行工具**

```bash
cd shu-reimbursement && bash scripts/setup_env.sh
```

### 二、日常三步

#### 第 1 步 · 把票据全扔进去

建一个自己的工作目录（名字随意），在它下面建 `截图暂存/`：

```
我的报销/
├── 截图暂存/     ← 所有票据都扔这里
├── 提交包/       ← 它自动生成，不用提前建
└── 参考/         ← 规则 PDF 与空白模板，首次让它自己下
```

**不用分类、不用改名、不用按日期排**，下面这些直接往里放：

| 类型 | 例子 |
|------|------|
| 截图 | 微信/支付宝支付记录、银行交易通知、打车行程、酒店确认单 |
| PDF / OFD | 电子发票、机票行程单、注册费通知函 |
| Excel / Word | 出差审批单、会议通知、邀请信 |
| 照片 | 纸质发票、出租车票、登机牌 |

⚠ **电子发票必须是 pdf/ofd 源文件**。只给截图会被财务退单——Agent 会把它列进缺件清单，但票得你自己去税局/商家页面下载。

#### 第 2 步 · 跟它说一句话

一句话里带上三件事：**报什么类型** + **什么时候去哪** + **用哪张卡**。

直接复制改：

> 帮我整理这个月的差旅报销：10 月 16–18 日去成都开学术会议，用 N 卡。

或者更省事：

> 整理报销，`截图暂存/` 里的都处理掉

它会先读票据，再问你缺的信息（比如「这次是公用经费还是项目经费？」「住宿是两人合住吗？」）。
**照实答，别让它猜**——经费卡、人数、天数任何一项猜错，整张单子要重填。

#### 第 3 步 · 去 `提交包/` 验收

生成的东西长这样：

```
提交包/202610成都/
├── 差旅_202610成都.xlsx         ← 填好的报销单 + 审批单
├── 差旅_202610成都_报销单.pdf    ← 可直接打印
└── README.md                   ← 状态板
```

先看 `README.md`：✅ 齐了什么、⚠️ 缺什么、💰 金额怎么算出来的。
补完缺件让它重跑一次 → 打印签字 → 去学校系统填报。

### 三、一个完整例子

```
你：整理报销，截图暂存里都处理
它：识别到 6 个文件：2 张机票行程单、1 张住宿发票、2 张支付截图、1 份会议通知。
    这次是 10/16–10/18 成都，用哪张经费卡？
你：N 卡
它：N 卡 → 非科研 → 走 127 号。核对结果：
    · 往返机票齐全，票面有 GP 单号，公务卡记录已配上
    · 住宿 ¥960 / 2 晚，未超成都限额（其余人员 500/天）
    · 会议通知写明「食宿统一安排、费用自理」→ 补助按 4 个自然日发，不是 2 天
    · 缺：注册费发票的源文件（现在只有截图）
    报销单已生成到 提交包/202610成都/，合计 ¥6,200.00
你：（补上注册费 pdf）
它：已重新核验，通过。可打印。
```

### 四、它会主动拦住的坑

这些不是"温馨提示"，是**拦住不让填错**：

- 只有交通票、没有住宿发票，却想算伙食补助 → 一般不得领取
- 公用经费在外省市同一城市超过 3 天 → 要必要性说明
- 从别的出差文件夹复制来的「错版表格」→ 逐格核对出差人 / 日期 / 卡号
- Excel 正开着这个文件（`~$` 锁文件）→ 不写，先让你关掉
- 会费 / 会员费想塞进差旅单 → 拒绝，改走日常报销
- 大写金额与公式结果对不上 → 不生成

### 五、只用命令行（不装 Agent）

```bash
bash scripts/setup_env.sh                      # 建 .venv

# 看当前表格的列宽/行高/打印设置
python scripts/patch_xlsx.py 差旅_202610成都.xlsx --show

# 调排版（只改 XML，保留签名图与富文本）
python scripts/patch_xlsx.py 差旅_202610成都.xlsx \
    --col O=12 --col L=8.2 --col N=1.0 --row 15=60 --fit-to-page

# 按真实几何重建 PDF（不依赖 LibreOffice）
python scripts/geometry_render.py 差旅_202610成都.xlsx 报销单.pdf \
    --sheet 上海大学国内差旅费报销单

# 逐格像素核验：底纹 / 边框 / 文字 / 裁切 / 签名图
python scripts/verify_cells.py 差旅_202610成都.xlsx 报销单.pdf PDF核验/
```

依赖：`reportlab` `openpyxl` `pdfplumber` `pillow` `pymupdf`；外部命令 `pdftotext` `pdftoppm` `pdffonts`（poppler）。

## 相对上游的改进

上游给的是**流程骨架**，本仓库补的是**规则精度与工程可靠性**。分三块讲清楚。

### 一、承袭上游的部分（这些不是我的功劳）

- 目录约定：`截图暂存/` 票据入口、`提交包/` 交付物、`参考/` 规则与模板、`存档/` 追踪
- 九大类关键词自动分类（差旅 / 会议 / 材料设备 / 版面印刷 / 劳务 / 国际交流 / 公务接待 / 技术服务 / 学生活动）
- 发票—支付**配对**，含银行立减容差（金额差 <2% 且同日 → 自动绑定）
- 改签/退票**闭环校验**：`原付 = 退款 + 退票费 + 改签票`
- 缺件检查、支付记录汇总、一句话触发「整理报销」
- `.xls` 含签名图**不程序化修改**这条铁律，也是上游先提出来的

### 二、我改进的（规则与表格）

| # | 维度 | 上游 README | 本仓库 |
|---|------|------|--------|
| 1 | 规则版本 | 基于《财务与资产业务百问百答》 | 加上 **上大内〔2026〕127/128 号**（2026-07-30 施行），并按**出差日**判断是否跨界、不回溯 |
| 2 | 判经费卡 | 无此环节 | **先判首字母**：`D V L` → 128 号（限额高、无 3 天限制）；`A C E J Q X B N P T` → 127 号 |
| 3 | 住宿限额 | 无分档表 | 按省市分档：非科研 3 档、科研 4 档（含二级教授档） |
| 4 | 市内交通 | 按包干处理 | **包干 80 元/天 与 凭票据实 二选一**，不能既包干又报票 |
| 5 | 会议/培训补助 | 只有「对方全包 → 只发在途」 | 补上「统一安排但**食宿自理** → 按**自然天数**全额发」分支。判据是**钱由谁出**，不是有没有统一安排 |
| 6 | 审批单坐标 | 未成文 | 精确到 2026 版 `A13` 时间 / `A14` 城市 / `A15` 事由 / `A19·C19` 经费账号 / `A20` 意见，**并与 2019 版逐格区分**（用错会整表填串） |
| 7 | 报销单坐标 | 未成文 | 精确到格，并写清三个致命细节：**交通行与补助行共用行号**、`O12 = O6+O7+O8`（漏写补助）、会务费**同时填 Q7 与 Q12** |
| 8 | 复选框 | 未涉及 | `□` 打勾用 **Wingdings 2 的字母 R** + `load_workbook(rich_text=True)`。否则 xlsx 里是裸 `R`，打印出来才对——这个坑不说破没人能猜到 |
| 9 | 排版 | 未涉及 | 列宽 `O=12 / L=8.2 / N=1.0`、大写行前导空格 3、**情况说明区行高公式** `行数×14.2+6`。不调就会出「1029 87」和「正文被整段裁掉」 |
| 10 | 防错 | 未涉及 | **错版表格逐格核对**（文件名对、内容是上一次行程）、`~$` 锁文件（Excel 开着就会被覆盖）、写完重读、改前备份 |
| 11 | 会费 | 未涉及 | 论证**学会会费不得进差旅单**：票据合规但科目超范围，单独走日常报销 |

> 上表对比基准是**上游仓库公开的 README** 所述能力范围。上游 `SKILL.md` 内部细节可能更多，
> 若某条其实上游已有、只是没写在 README 里，欢迎 PR 指正——这正是写这份对照表的目的：**把功劳归对地方**。

### 三、我新做的（上游没有的）

| 新增 | 解决什么 |
|------|----------|
| **分层结构**：`SKILL.md` 门面 + 12 章 `references/` | 单文件 487 行一次性塞进上下文，Agent 反而抓不住重点。现在门面只留三条前置判断 + 路由表 |
| **`references/08` 出国（境）报销** | PIM 与智能报销双线（PIM 审完 ≠ 钱到账）、7 项凭证、柜照 5 日、Airbnb 住宿口径、合住分摊、未成行口径 |
| **`references/09` 日常报销科目口径** | 办公费 vs 材料费判据、400–1000 元 10 类低值物资、**市财政包干制负面清单**、退单整改路径 |
| **`scripts/geometry_render.py`** | 无 LibreOffice 也能导 PDF：按真实列宽/行高/底纹/边框重建，全量嵌入 TTF，不再出「1029 87」 |
| **`scripts/verify_cells.py`** | 逐格像素核验：底纹、边框缺失/多余、文字墨迹、裁切、签名图位置偏差（容差 0.8pt）。不再靠肉眼看缩略图 |
| **`scripts/compare_pdf.py`** | 与「别人导出的 PDF」比对 + **版本指纹**：分清「我渲染错了」和「用户改了列宽」 |
| **`scripts/patch_xlsx.py`** | 把手工 XML 手术固化成工具：列宽能拆分 `min/max` 分组、保留 `hidden`、行高、`fitToPage`、`--show` 自检 |
| **PDF 叠层中文标注**（`references/11` §10） | 境外凭证加中文批注：reportlab 画透明叠层 + `show_pdf_page` + `saveIncr`，52KB → 114KB。附「别用 `insert_font`，否则 23MB 超单件上限」的教训 |
| **全仓脱敏** | 见下节 |

> 一句话总结：上游回答「流程怎么走」，本仓库回答「这一格填什么、为什么不能填、填错了会怎么退」。

## 脱敏说明

本仓库**不包含**任何真实报销数据。相对工作副本，已删除或泛化：

- 真实姓名、工号、审核人工号
- 真实经费卡号（统一改为 `N.14-GXXX-26-XXX` / `D.69-0000-26-000` 形式）
- 银行卡尾号、报销单号、批件号、团组流水号
- 本机绝对路径（改为相对路径或 `$VENV`）
- 校内未公开文件（规则 PDF、空白模板**不随仓库分发**，只说明获取方式）

保留的金额与标准都是**公开的限额数字**或示例算例。

## 免责声明

本技能是**辅助工具**，不构成财务或法律意见。

- 所有标准、限额、审批权限以财务处**当期正式文件与柜台审核结论**为准。
- 规则会变。用之前先看 `references/00` 的「规则版本与优先级」，核对是否已出新办法。
