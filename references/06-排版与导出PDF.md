# 06 · 排版与导出 PDF

两个场景，别混：

- **A · 用户自己在 Excel 里「另存为 PDF」** → 本节 §1–§4。xlsx 的列宽/行高**直接决定**打印效果，必须预调。
- **B · 用本技能重建 PDF**（无 LibreOffice / 要可验证） → 见 `07-工具-xlsx渲染核验.md`。

## 1. 列宽与行高（场景 A 必调）

| 位置 | 值 | 不这么做的后果 |
|------|-----|----------------|
| 列 **O**（住宿/小计金额） | **12** | 太窄 → `1029.87` 导成「1029 87」 |
| 列 **L**（人数/发票金额值） | **8.2** | 太窄 → `1029.87` 截成「1030」 |
| 列 **N** | **1.0** | 工作区惯用值，保持多处一致 |
| H13「合 计 金 额 （大写）：」后空格数 | **3** | 模板默认 11 → 金额稍长就在格内**换行** |
| H14「财务复核金额（大写）：」后空格数 | **3** | 同上 |
| 行 **15/16/17**（情况说明区 A15:J17） | 按字数放大，见 §2 | 默认 13.5pt 只放得下 3 行，正文被**整段裁掉** |

## 2. ★情况说明区行高估算

默认行高 13.5pt × 3 行 ≈ 只装得下 3 行文字。说明一写长就被裁，且**打印出来毫无提示**。

```
总高 = 行数 × 14.2 + 6
三行均分：每行 = 总高 / 3
```

**行数怎么估**：按**全角单位**计宽，一行容量 ≈ **22.5 单位**。

| 字符型 | 折算 |
|--------|------|
| CJK（汉字、中文标点） | 1 单位 |
| ASCII（字母、数字、半角符号） | 0.5 单位 |

> 直接用 `len()` 会**严重低估**——ASCII 占半宽。必须按上表逐字符折算再除以 22.5 向上取整。

算例：

| 文本 | 字符数 | 折算单位 | 行数 | 总高 |
|------|--------|----------|------|------|
| 纯中文 272 字 | 272 | 272 | 13 | 190.6 |
| 中文 284 字 + 部分英文 | 284 | 255 | 12 | 176.4 |
| 中文 318 字 | 318 | 318 | 15 | 219.0 |

## 3. 改法：zip 级 XML 手术，别整表重存

`openpyxl` 保存会**重写列分组、丢 `<pageSetUpPr>`、可能塞一个写死的 `scale`**。表宽一改，固定缩放就让 PDF 横向分成 2 页。

**正确做法**：解 zip → 改 XML → 重新打包。目标文件：

| 内容 | 文件 |
|------|------|
| 列宽、行高 | `xl/worksheets/sheetN.xml` 里的 `<cols><col .../></cols>` 与 `<row r="15" ht="54.1" .../>` |
| 单元格文字 | `xl/sharedStrings.xml` |
| 打印设置 | `xl/worksheets/sheetN.xml` 的 `<sheetPr>` / `<pageSetup>` |
| 签名图片 | `xl/media/image*.{jpeg,png}` —— **必须原样保留** |

⚠ 三个细节：

1. `<col>` 可能是**分组**（`min="1" max="2"`、`min="16" max="17"`）且带 `hidden="1"` → 按 **min/max** 匹配，不要按列字母猜。
2. 字符串有两种存法：
   - Excel 保存 → `sharedStrings.xml`（`<si><t>...</t></si>`）
   - openpyxl 保存 → `t="inlineStr"` + 中文数字实体（`&#21512;`）
   → 解码用 **`html.unescape`**（⚠ `xml.sax.saxutils.unescape` **不解数字实体**），回写用 `escape()` 并加 `xml:space="preserve"`。
3. 改完**逐格 diff**：确认只有目标格变了，其余单元格与原文件完全一致。

**用现成工具**：

```bash
python scripts/patch_xlsx.py 表.xlsx \
  --col O=12 --col L=8.2 --col N=1.0 \
  --row 15=60 --row 16=60 --row 17=60 \
  --fit-to-page
```

## 4. 打印设置（加宽后必做）

```xml
<sheetPr><pageSetUpPr fitToPage="1"/></sheetPr>
<pageSetup fitToWidth="1" fitToHeight="0" orientation="portrait" .../>
```

- **不要留写死的 `scale="94"`**：加宽后表宽可能到 625pt > 可打印 559pt，固定缩放必然横向分 2 页。
- `fitToHeight="0"` = 高度不限，只压宽度。

## 5. 定位「导出 PDF 数字乱码」

现象：`1029.87` → `1029 87`（丢小数点）或 `1030`（变值），而中文都正常。

**多半是导出端的字库子集 bug，不是列宽问题**：

```bash
pdffonts out.pdf                  # 找 encoding=WinAnsi、uni=no 的子集（无 ToUnicode）
pdftotext -layout out.pdf - | head -50
```

判据：数字写在中文串里显示正常，**独立的中文灰底数字格**出错 → 导出端 ASCII 字体子集坏了。

处置：① 让对方改用 Excel 自带「导出 → 创建 PDF」；② 或用本技能 `scripts/geometry_render.py` 自己渲染（全量嵌入 TTF，不丢字形）。

## 6. 交付前肉眼核对

```bash
pdftoppm -r 110 -png out.pdf chk     # 转图看版式
```

重点看四处：列宽是否够、大写金额有没有换行、情况说明有没有被裁、签名图在不在框内。
